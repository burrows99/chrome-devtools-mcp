# Build & Tooling — Overview

> **Layer:** Build & tooling · **Sources:** `package.json`, `scripts/`, `.github/workflows/`, `tsconfig.json`, `rollup.config.mjs`, `eslint.config.mjs` · **Verified at:** commit afa5622 (2026-06-19)

## Purpose
The build & tooling layer turns the TypeScript source into a runnable + publishable npm package, keeps generated docs/CLI/metrics in sync with the tool definitions, vendors the Lighthouse engine, and gates everything through CI. This is the developer-facing machinery, not the runtime.

## Key files
- `package.json` — every npm script (the entrypoints to all tooling)
- `tsconfig.json` / `scripts/tsconfig.json` — compiler config for app vs. scripts
- `rollup.config.mjs` — produces the single-file `third_party` bundle + license notices
- `scripts/*.ts|.mjs` — generators, verifiers, eval/metrics tooling (see [scripts-reference](scripts-reference.md))
- `scripts/eslint_rules/` — three custom ESLint rules
- `.github/workflows/*.yml` — presubmit, tests, release-please, publish

## How it works
Two distinct flows:

**Build vs. bundle.** `npm run build` = `tsc` + `post-build.ts` (compiles to `build/`, plus DevTools shims). `npm run bundle` does a clean build then runs Rollup to inline `node_modules` into `src/third_party/*.js` self-contained ESM, deletes `build/node_modules`, and appends Lighthouse notices. The npm package ships only the bundle. See [build-and-bundle](build-and-bundle.md).

**Regeneration pipeline** — `npm run gen`:
```
npm run build          # compile first (generators import from build/)
&& npm run docs:generate   # docs/tool-reference.md, slim-tool-reference.md, README sections
&& npm run cli:generate    # src/bin/chrome-devtools-cli-options.ts
&& npm run update-metrics  # src/telemetry/*_metrics.json
&& npm run format          # eslint --fix + prettier
```
All four generators read the *compiled* tool definitions, so a stale build produces stale docs. See [code-generation](code-generation.md), [eval-and-metrics](eval-and-metrics.md).

**CI gates** (PR + merge_group): `presubmit.yml` runs `check-format` and `check-docs` (runs `npm run gen` and fails if the tree changed). `run-tests.yml` is a 3×3 OS/Node matrix. `conventional-commit.yml` validates PR titles. Release/publish is automated via release-please → tag → npm + MCP registry. See [ci-and-release](ci-and-release.md), [config-files](config-files.md), [lighthouse-vendoring](lighthouse-vendoring.md).

## Relationships
- **Depends on:** the tool definitions in `src/tools/` (read by the generators), `src/telemetry/` (metrics registry), the Lighthouse checkout next to the repo.
- **Produces / affects:** `build/` output consumed by [entrypoints](../01-entrypoints/README.md); the `src/third_party` bundle consumed by [Performance & memory](../06-performance-memory/README.md) and [Browser/CDP](../04-browser-cdp/README.md); generated docs in `docs/`; CLI options in `src/bin/`.

## Gotchas & non-obvious details
- Generated files carry `DO NOT EDIT` / `Auto-generated by 'npm run gen'` headers — never hand-edit.
- Generators `import` from `build/...`, so `build` MUST run first in `gen`.
- The published package contains the Rollup bundle, **not** `build/node_modules`.

## Update triggers
- A new npm script is added or an existing one is rechained.
- A CI workflow changes.
- The build/bundle topology (tsc, post-build shims, rollup inputs) changes.
