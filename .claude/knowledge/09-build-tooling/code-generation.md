# Code Generation

> **Layer:** Build & tooling · **Sources:** `scripts/generate-docs.ts`, `scripts/generate-cli.ts` · **Verified at:** commit afa5622 (2026-06-19)

## Purpose
Two generators keep human/agent-facing artifacts in lock-step with the tool definitions: the Markdown tool reference + README sections, and the CLI command/option table. Both run inside `npm run gen` after `build`.

## Key files
- `scripts/generate-docs.ts` — writes `docs/tool-reference.md`, `docs/slim-tool-reference.md`, and two README regions
- `scripts/generate-cli.ts` — writes `src/bin/chrome-devtools-cli-options.ts`

## How it works
**`docs:generate` → `generate-docs.ts`** reads tools directly from the compiled `createTools()` (called twice: `{slim:false}` and `{slim:true}`). For each tool it walks the Zod schema (`getZodTypeInfo` unwraps `ZodOptional`/`ZodDefault`/`ZodEffects` to derive type, enum, default, required) and emits Markdown:
- File header `<!-- AUTO GENERATED DO NOT EDIT - run 'npm run gen' to update-->`.
- Tools grouped by `annotations.category`, ordered by the `ToolCategory` enum, with off-by-default categories pushed last and annotated with their `--flag`.
- `addCrossLinks` turns tool-name mentions into anchor links; `escapeHtmlTags` escapes `<...>`.
- Skips `IN_PAGE` tools and `get_tab_id`.
- Updates `README.md` between `<!-- BEGIN/END AUTO GENERATED TOOLS -->` (the TOC) and `<!-- BEGIN/END AUTO GENERATED OPTIONS -->` (CLI options table, built from `cliOptions`, skipping `hidden`, rendering camelCase + dash-case names, type/choices/default).

**`cli:generate` → `generate-cli.ts`** is heavier: it actually *spawns the built MCP server* (`build/src/bin/chrome-devtools-mcp.js --viaCli`) over a `StdioClientTransport`, calls `listTools()`, and merges the live tool list with the static `createTools(parseArguments())` to read each tool's `annotations.category`/`conditions`. It then:
- Filters out `fill_form`, `wait_for` (array/JSON args don't map to CLI), `get_tab_id`, and `IN_PAGE` tools.
- Appends `(requires flag: --<category>=true, --<condition>=true)` to descriptions for off-by-default categories (`buildFlag`) and conditional tools.
- Converts each tool's JSON Schema into a `commands` record and writes it as a typed `export const commands` to `src/bin/chrome-devtools-cli-options.ts` with header `// NOTE: do not edit manually. Auto-generated by 'npm run cli:generate'.`

## Relationships
- **Depends on:** compiled `build/src/tools/tools.js` (`createTools`), `build/src/tools/categories.js` (`ToolCategory`, `labels`, `OFF_BY_DEFAULT_CATEGORIES`, `buildFlag`), and (for CLI) a runnable built server. Tool source lives in [tools layer](../02-tools/README.md).
- **Produces / affects:** `docs/tool-reference.md`, `docs/slim-tool-reference.md`, README regions, and `src/bin/chrome-devtools-cli-options.ts` consumed by [entrypoints](../01-entrypoints/README.md).

## Gotchas & non-obvious details
- Both generators import from `build/...`, so `npm run gen` builds first; running them against a stale `build/` yields stale docs (CI's `check-docs` catches drift).
- `generate-cli.ts` is the only generator that boots a real server process — it needs the build to actually start (sets `CHROME_DEVTOOLS_MCP_NO_USAGE_STATISTICS=true`).
- Zod default extraction calls `def.defaultValue()` — defaults must be serializable.

## Update triggers
- Tool schemas, categories, conditions, or `cliOptions` change.
- The `DO NOT EDIT` markers in README/docs are renamed.
- A tool needs to be (un)hidden from CLI/docs (edit the filter lists).
