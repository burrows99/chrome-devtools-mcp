# Formatters

> **Layer:** Formatters · **Sources:** `src/formatters/`, `src/issue-descriptions.ts` · **Verified at:** commit afa5622 (2026-06-19)

## Purpose
Formatters turn raw collected data (console messages, uncaught errors, network requests, DevTools issues, accessibility snapshots, heap-snapshot aggregates) into **token-efficient** output for the MCP agent. Each formatter produces two parallel representations: a compact human-readable **text** form and a structured **JSON** form that is mirrored into the MCP response's `structuredContent`.

## Key files
- `ConsoleFormatter.ts` — console messages + uncaught errors → text/JSON; consecutive-message grouping. See [console-formatter.md](./console-formatter.md).
- `NetworkFormatter.ts` — HTTP requests/responses → text/JSON; body truncation, header redaction, redirect chains. See [network-formatter.md](./network-formatter.md).
- `IssueFormatter.ts` — aggregated DevTools issues → text/JSON; markdown descriptions, affected resources. See [issue-formatter.md](./issue-formatter.md).
- `SnapshotFormatter.ts` — accessibility (a11y) tree → indented text/JSON. See [snapshot-formatter.md](./snapshot-formatter.md).
- `HeapSnapshotFormatter.ts` — heap aggregates / nodes / edges / retaining paths / dominators → CSV-style text + JSON. See [heap-snapshot-formatter.md](./heap-snapshot-formatter.md).
- `../src/issue-descriptions.ts` — loads bundled DevTools issue-description markdown into an in-memory cache; consumed only by `IssueFormatter`.

## The concise-vs-detailed pattern
Every per-item formatter exposes **two altitudes** of output, because the agent first lists many items cheaply, then drills into one:

| Altitude | Text method | JSON method | Internal type |
|----------|-------------|-------------|---------------|
| **Concise** (list rows) | `toString()` | `toJSON()` | `*Concise` interface |
| **Detailed** (single item) | `toStringDetailed()` | `toJSONDetailed()` | `*Detailed extends *Concise` |

- The detailed JSON type **extends** the concise type (`ConsoleMessageDetailed extends ConsoleMessageConcise`, `NetworkRequestDetailed extends NetworkRequestConcise`, `IssueDetailed extends IssueConcise`), so detail is strictly additive.
- Concise rows carry a stable `id`/`requestId`/`reqid`/`msgid` and minimal fields (type, text, status, count). Detailed adds heavy payloads: resolved args, stack traces, request/response bodies, headers, full markdown descriptions, affected resources.
- **Token rationale:** expensive data (stack symbolization, post/response bodies) is only fetched when detailed output is requested. The `fetchDetailedData` / `fetchData` option on `ConsoleFormatter.from` / `NetworkFormatter.from` gates the CDP round-trips that populate the detailed fields. List paths pass `false`; single-item drill-down paths pass `true`.

## Shared conventions
- **Static async `from(...)` factories** where I/O is needed (`ConsoleFormatter.from`, `NetworkFormatter.from`); plain constructors where data is already in memory (`IssueFormatter`, `SnapshotFormatter`, `HeapSnapshotFormatter`).
- **Text helpers are free functions**, not methods — `toString*` delegates to a `convert*ToString` function that takes the JSON shape. This keeps the JSON shape as the single source of truth: text is derived from JSON, never the reverse.
- **Stable IDs** are injected by the caller (`McpContext`), not generated by formatters. Formatters never own identity.
- **Markdown section headers** (`## …`, `### …`) structure detailed text output; `IssueFormatter` strips a leading `# ` from issue markdown to avoid clashing with the response's own heading hierarchy.
- **Graceful degradation:** every fetch path swallows errors and substitutes a sentinel string (`<Request body not available anymore>`, `<binary data>`, `<error: Argument N is no longer available>`).

## Relationships
- **Depends on:** raw collected data from [Collectors / context state](../03-context-state/) (`PageCollector`, `McpContext` accessors), DevTools front-end utilities re-exported via `src/third_party/index.js` (stack-trace model, `IgnoreListManager`, `NetworkRequestFormatter.sanitizeHeaders`, `MarkdownIssueDescription`, `Marked`, `I18n.ByteUtilities`), and `src/devtools/DevtoolsUtils.ts` (`SymbolizedError`, `createStackTraceForConsoleMessage`).
- **Used by:** [`McpResponse`](../03-context-state/) (`src/McpResponse.ts`) is the sole orchestrator — it constructs formatters, chooses concise vs detailed, paginates, optionally TOON-encodes JSON, and writes both `content` (text) and `structuredContent` (JSON). The [Tool system](../02-tools/README.md) feeds the response via `response.attach*` / `response.set*` methods.

## Gotchas & non-obvious details
- Text and JSON for the **same item must not disagree** — see the explicit comment in `NetworkFormatter` about not re-reversing the redirect chain (the JSON already ordered it).
- TOON encoding (`toonEncode`) is an alternate, even-more-compact text serialization of the JSON applied at the `McpResponse` layer, not inside formatters.
- Body/stack size caps live in the formatters (`BODY_CONTEXT_SIZE_LIMIT = 10000`, `STACK_TRACE_MAX_LINES = 50`).

## Update triggers
- A new formatter is added under `src/formatters/`.
- The concise/detailed JSON shapes change (fields added/removed/renamed).
- Output column order, text headers, or sentinel strings change.
- Token-limit constants (`BODY_CONTEXT_SIZE_LIMIT`, `STACK_TRACE_MAX_LINES`) change.
