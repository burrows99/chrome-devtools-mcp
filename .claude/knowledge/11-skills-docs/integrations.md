# Editor / Client Integrations

> **Layer:** Skills, docs & integrations · **Sources:** `.claude-plugin/marketplace.json`, `.claude-plugin/plugin.json`, `.cursor-plugin/plugin.json`, `.gemini/settings.json`, `gemini-extension.json`, `README.md` (install sections) · **Verified at:** commit afa5622 (2026-06-19)

## Purpose
Manifest files that let editors/agent clients install `chrome-devtools-mcp` as a first-class plugin/extension — bundling the **MCP server + skills** together — rather than just registering a bare MCP server. Each manifest wires the same `npx chrome-devtools-mcp@<version>` command; the value-add over a plain `mcp add` is that the skills ride along.

## Key files / dirs
- `.claude-plugin/marketplace.json` — Claude Code marketplace registry (lists the plugin)
- `.claude-plugin/plugin.json` — Claude Code plugin manifest (MCP server def)
- `.cursor-plugin/plugin.json` — Cursor plugin manifest
- `gemini-extension.json` — Gemini CLI extension manifest (repo root)
- `.gemini/settings.json` — Gemini context-file config (AGENTS.md / GEMINI.md)

## How README documents per-client install
- **Plugin (MCP + skills)** is the recommended path for Claude Code, Gemini CLI (extension), and Copilot/VS Code ("Chat: Install Plugin From Source" → `ChromeDevTools/chrome-devtools-mcp`). These bundle server + skills.
- **Bare MCP server (no skills)**: `claude mcp add chrome-devtools --scope user npx chrome-devtools-mcp@latest`; `gemini mcp add chrome-devtools npx chrome-devtools-mcp@latest`; Cursor deeplink / manual `New MCP Server`.
- README also covers Cline, Gemini Code Assist, and others, all pointing at the same `npx chrome-devtools-mcp@latest` config.

## Relationships
- **Depends on / generated by:** Hand-maintained; versions are pinned and bump with the package release (currently `1.3.0`). Not produced by a generator.
- **Surfaces:** Each manifest launches the server entrypoint `chrome-devtools-mcp` (bin in package.json → `build/src/bin/chrome-devtools-mcp.js`, see [01-entrypoints](../01-entrypoints/)) and delivers the [agent skills](agent-skills.md).

## Gotchas & non-obvious details
- All four MCP manifests pin `@1.3.0` (not `@latest`) and the marketplace/plugin/extension `version` fields are also `1.3.0` — these must be bumped in lockstep on release. README install snippets, by contrast, use `@latest`.
- `.gemini/settings.json` is easy to mistake for an MCP config but only declares context filenames; the actual Gemini MCP/extension wiring is in `gemini-extension.json`.
- Claude marketplace plugin install clones the repo over HTTPS; behind firewalls it can fail with `Failed to clone repository` — documented in [docs-reference.md](docs-reference.md) (`docs/troubleshooting.md`), with SSH-redirect and bare-`mcp add` workarounds.
- The Claude plugin `source: "./"` means the marketplace serves the plugin from the repo root, so `.claude-plugin/`, `skills/`, and the package together form the installable unit.

## Update triggers
- Package version bump → update version in all four manifests.
- A new client/editor is supported → README install section + possibly a new manifest dir.
- Gemini context-file conventions change → `.gemini/settings.json`.
