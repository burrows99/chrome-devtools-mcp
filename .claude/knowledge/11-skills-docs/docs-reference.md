# Docs Reference (`docs/`)

> **Layer:** Skills, docs & integrations · **Sources:** `docs/cli.md`, `docs/tool-reference.md`, `docs/slim-tool-reference.md`, `docs/design-principles.md`, `docs/debugging-android.md`, `docs/third-party-developer-tools.md`, `docs/troubleshooting.md` · **Verified at:** commit afa5622 (2026-06-19)

## Purpose
The `docs/` directory holds human-facing documentation linked from `README.md`. It is **not** part of the published npm package (package.json `files` lists `build/src`, `LICENSE`, `skills` — not `docs`), so these docs live on GitHub/the repo. Two of them are machine-generated and carry a "DO NOT EDIT" header.

## Key files / dirs
- `docs/tool-reference.md` — full per-tool reference (**AUTO-GENERATED**)
- `docs/slim-tool-reference.md` — the 3 tools available in `--slim` mode (**AUTO-GENERATED**)
- `docs/cli.md` — the experimental CLI (hand-written, documents generator behavior)
- `docs/troubleshooting.md` — connection/setup problems & fixes
- `docs/design-principles.md` — guidelines for shipping new tools
- `docs/debugging-android.md` — experimental Android remote-debugging setup
- `docs/third-party-developer-tools.md` — page-exposed 3p tool API

## Relationships
- **Depends on / generated by:** `tool-reference.md` + `slim-tool-reference.md` ← `scripts/generate-docs.ts` (run via `npm run gen` → `docs:generate`). See [code-generation](../09-build-tooling/code-generation.md).
- **Surfaces:** Documents the MCP tools in [02-tools](../02-tools/), the CLI/entrypoints in [01-entrypoints](../01-entrypoints/), and feeds the `troubleshooting` skill ([agent-skills.md](agent-skills.md)).

## Gotchas & non-obvious details
- Only the two `*-tool-reference.md` files are generated; everything else in `docs/` is hand-maintained. Editing the generated files by hand will be overwritten by `npm run gen`.
- `npm run gen` = `build` → `docs:generate` → `cli:generate` → `update-metrics` → `format`; there is no standalone `npm run docs`.
- `docs/cli.md` documents that the CLI generator (`scripts/generate-cli.ts`) excludes `wait_for` and `fill_form`, and that server args are filtered in `src/bin/chrome-devtools.ts`.

## Update triggers
- A tool is added/changed/removed → run `npm run gen` → re-verify the two generated reference tables.
- A new troubleshooting symptom or supported client is documented.
- `--slim` toolset changes → `slim-tool-reference.md` regenerates.
