# Project memory — chrome-devtools-mcp

This is the **Chrome DevTools MCP server + CLI**: it gives AI agents control of a
live Chrome browser via MCP, using Puppeteer/CDP plus a vendored slice of Chrome
DevTools Frontend / Lighthouse for inspection and performance analysis.

> The build/test/style rules above come from `AGENTS.md` (imported). Follow them.

## Knowledge library — read this first
A layered, navigable reference for the whole codebase lives in
[`.claude/knowledge/`](./knowledge/README.md). It goes high-level → low-level
across 13 layers (overview → entrypoints → tools → context → browser/CDP →
formatters → perf/memory → telemetry → utils → build → testing → skills/docs →
conventions).

**Before non-trivial work:** open [`knowledge/README.md`](./knowledge/README.md)
and read the relevant layer. To find the doc for a file you're touching:
`grep -rl "src/path/you/changed" .claude/knowledge`.

## Must-know facts
- **`McpContext` (`src/McpContext.ts`) is the hub** — it bridges ~16 subsystems
  (pages, collectors, snapshots, emulation, heap, third-party tools). Changes
  there ripple widely. See [knowledge/03-context-state/mcp-context.md](./knowledge/03-context-state/mcp-context.md).
- **Much of perf/trace code is vendored**, not first-party: a minified
  `chrome-devtools-frontend`/`lighthouse` bundle regenerated by
  `scripts/update-lighthouse.ts`. Don't try to "fix" it line-by-line. See
  [knowledge/06-performance-memory](./knowledge/06-performance-memory/README.md).
- **Some docs are generated.** `docs/tool-reference.md` and
  `docs/slim-tool-reference.md` have "DO NOT EDIT" headers — edit the tool source
  and run `npm run gen` instead.

## Workflow rules (beyond AGENTS.md)
- After adding/renaming/redescribing a tool, run **`npm run gen`** (regenerates
  tool docs, CLI, metrics).
- Tool argument schemas (Zod): **no `.nullable()`, no `.object()`** — enforced by
  the `@local/enforce-zod-schema` ESLint rule. Model complex objects as short
  formatted strings.
- Conventional Commits for titles; `chore:` for not-yet-released features,
  `feat:` to enable them. See [knowledge/12-conventions](./knowledge/12-conventions/README.md).
- Tools should follow the [design principles](./knowledge/12-conventions/design-principles.md):
  token-optimized output, small deterministic blocks, self-healing errors,
  reference-over-value for heavy assets.

## Maintaining the knowledge library
The library is a **derived artifact** — code is the source of truth. When you
change code, update the affected knowledge doc(s) in the same change. Each doc's
`## Update triggers` section says when it's stale; the mapping table and the
link-integrity check are in
[`knowledge/MAINTENANCE.md`](./knowledge/MAINTENANCE.md). If a doc and the code
disagree, trust the code and fix the doc.
